### Analysis of the Android app
Fully read. Key facts:
- `com.example.network.P2PProtocol` — JSON packet `{type,senderId,senderName,targetId,payload,msgId,extraData?}`
- `com.example.network.LocalP2PServer` — TCP `:8888`; frame = `[magic 1B][len 4B BE][JSON UTF-8]`;
  magic `0x01` = signal, `0x02` = file header followed by encrypted payload.
  UDP broadcast listener `:8887` (239.255.0.1 / 255.255.255.255 / subnet broadcast).
- `com.example.network.BinaryStreamRelay` — 16-byte random IV + **AES-256-CTR**; key =
  `"P2P_TACTICAL_DIRECT_BINARY_KEY"` UTF-8 (30 bytes) zero-padded into 32 bytes.
- `com.example.network.NsdHelper` — mDNS `_walkietalkie._tcp`, instance `WT-<displayName>`,
  TXT `displayName`, `model`.
- `com.example.network.UdpAudioEngine` — walkie audio **UDP :9999**, raw PCM s16le 16 kHz mono.
- `com.example.network.LocalCallEngine` — **NOT real WebRTC**. Signalling uses fake SDP strings;
  real media is raw UDP: **audio :8890** (PCM s16le 16 kHz mono), **video :8889** (raw JPEG <60000 B,
  ~480x360, quality 35). This is why Android↔Linux calls can work.
- `P2PRepository` — 6 s heartbeat, 30 s /24 sweep, packet-loss watchdog (30%/5 s), 2-day auto-delete.

### Bugs already found and FIXED (do not regress)
1. `FrameReader.push` used `Buffer` (the class) instead of the chunk → total packet failure.
2. `mdns.buildMessage` needed `records = []` default → crash on query.
3. `netutil` broadcast used `~(ip & mask) + 1` (signed 32-bit) → produced `63.88.0.0`. Fixed to
   `(ip | ~mask) >>> 0` → now `192.168.0.255`.
4. File receive used `socket.pause()` + listener swap → **stream truncation**. Replaced with
   pull-based `FrameReader.setRawHandler()` + `FileDecryptStream`; one `'data'` listener for the whole
   connection.
5. `FileDecryptStream.finalize()` now verifies `expectedLength` and rejects on mismatch.
6. **Microphone always reported "unavailable"** — `audio.js` built the AudioWorklet from a
   `Blob` URL, but the renderer CSP is `script-src 'self'` with no `blob:` allowance, so
   `addModule()` was blocked and `ensureWorklet()` threw *before* `getUserMedia()` was ever
   called. The worklet now lives in `src/renderer/pcm-tap.js` and loads same-origin, so the
   CSP stays strict.
7. **Push-to-talk never transmitted** — `app.js` did `$('pttLabel')` but the markup only had
   `class="ptt-label"`. Every button press threw a `TypeError` and showed a misleading
   "Microphone unavailable" toast. Added `id="pttLabel"`.
8. **Duplicate top-level `const`** across `audio.js`/`app.js` is a *fatal* SyntaxError for the
   whole classic script (the app silently does nothing). Renamed to `VIS_BAR_COUNT`, and
   `scripts/renderer-check.js` now detects this class of bug automatically.
9. **electron-builder packaging defects** — nested `desktop.entry` emitted a literal
   `entry=[object Object]` line and dropped `Categories`; pointing `icon` at a directory
   produced a bogus `2x2` icon; `build/icons` was missing from the asar so the window icon
   never resolved. All fixed in `package.json`.
10. **First-run EULA trap** — electron-builder's generated `AppRun` always shows a zenity/kdialog
    licence dialog whose *Disagree* button exits silently, and its `APPDIR` detection breaks when
    arguments are passed (`! -e "$path/$1"`). `scripts/build-appimage.sh` now writes its own
    `AppRun`: no EULA, robust `APPDIR`, automatic `--no-sandbox`.

### AppImage runtime: upgraded to a static FUSE3 build

electron-builder ships the 2019 `appimage-12.0.1` runtime, which hard-requires the host to
provide `libfuse.so.2` (verified in its strings: `"dlopen(): error loading libfuse.so.2"`,
`"AppImages require FUSE to run."`). Per the official AppImage wiki, Ubuntu >= 24.04 and
Debian >= 13 do **not** ship `libfuse2` by default, so a large slice of users would hit a
cryptic failure on double-click.

`scripts/build-appimage.sh` now uses the modern `AppImage/type2-runtime` stub, which is
**statically linked (`not a dynamic executable`) and embeds squashfuse**. Consequences:
* no `libfuse2`/`libfuse3` package needed on any distro;
* the launcher itself has **no shared-library dependencies at all**;
* the earlier FUSE hang in this container disappeared — the AppImage now launches
  **directly via FUSE** here, which was previously impossible.

`file dist/*.AppImage` => `ELF 64-bit LSB pie executable, x86-64, static-pie linked`.

## GOTCHAS TO REMEMBER
- The file-writing tools **decode HTML entities inside `.js` files**. If you need `&`-style
  entities in JS, build them with `String.fromCharCode(38)` (see `escapeHtml` in
  `src/renderer/app.js`). HTML files are unaffected.
- `list_files` / `search_files` / `read_file` fail in this environment: **"Could not find ripgrep
  binary"**. Use `execute_command` with `ls`/`find`/`cat`/`sed`/`grep` instead.
- An Oracle Java language-server extension interferes with editing `.java` files in this workspace;
  write Java scratch files to `/tmp`.
- `apply_diff` can fail with "100% similarity required" on some blocks; fall back to a
  `python3` heredoc doing a string replace.
- **Renderer scripts are classic `<script>` tags sharing ONE global lexical scope.** A duplicate
  top-level `const`/`let`/`class` across `audio.js` / `app.js` / `pcm-tap.js` is a fatal
  SyntaxError that silently kills the entire file — the app then "starts" but does nothing.
  `scripts/renderer-check.js` now guards against this.
- **`pkill -f <pattern>` matches the invoking shell's own command line.** If the pattern appears
  anywhere in the command you are running (including a path you `cd`'d into), `pkill -f` kills
  your own test shell and you get "no output" instead of a result. Put such tests in a script file.
- Renderer top-level `const`s are NOT reachable from `webContents.executeJavaScript`
  (`typeof audio === "undefined"`); only things explicitly on `window` (e.g. `window.AudioEngine`,
  `window.walkie`) are. Assert on the DOM instead.
- **The CSP is `script-src 'self'` with no `blob:`** — never introduce a `Blob`-URL AudioWorklet,
  worker, or script. Put it in a real file next to the page.
